# 实际完成

## endpoint

- 在基于link_me实现的静态加载方法的基础上实现了endpoint功能
- 该功能实现为一个macro，由kernel提供。上层内核服务需要调用其他服务暴露接口时使用call！()这个宏
  - 参数1:crate名::函数名->举例：mm::mmap
  - 参数2:入参，如a:usize
  - 参数3:返回值，如Result<>
- kernel提供的call!将参数解析，在hashmap中查找先前注册的函数，检查参数是否匹配，并将先前存入的函数地址解析，执行该函数

- 如何注册接口
  - 使用#[safeos_export]标注的函数会在编译时被内核解析，注册在hashmap中
- 还没有将unwind并入

## redox

### syscall

- redox系统服务，pm，mm使用的接口也是posix like的，如open/close/mmap等
- syscall分发由kernel_scheme trait实现，pm,mm分别实现该trait，在相应函数(open/close)中完成syscall任务
- 如果单看代码结构的话，scheme的syscall分发机制不单单完成了分发，每个系统调用都在scheme被分为对pm和mm的多次调用。scheme完成了一些本应分配给pm mm做的任务。
- 如果要将pm mm完全独立出来，类似cantrip/sel4。还需设计自己的syscall 翻译/分发 层。并确定分发层的功能，也就是pm和mm是否要有部分实现在kernel中。

### pm/mm

- pm与mm耦合度高

  - 以spawn为例，创建一个新的thread，spawn函数在pm中。pm直接对mm的函数进行函数调用。

  |         PM         |                        MM                         |
  | :----------------: | :-----------------------------------------------: |
  |  set_addr_space()  |       这个函数初始化的数据结构在PM中被定义        |
  |    Kstak::new()    | 初始化一个内核栈，使用allocate_p2frame,分配物理页 |
  | Kstak::initial_top |      使用rmm_repo中的phys2virt，转为虚拟地址      |
- mm拥有一个类似于HAL层的简单抽象，rmm
  - rmm将内存管理部分的体系结构相关操作封装为体系结构无关，并支持riscv
  - rmm包含的功能有页表，物理页分配，页映射
  - pm并没有相应的封装且pm会有直接调用rmm中接口的情况
- pm使用的线程模型为1:1，且redox有进程概念。

### 外设

- 简单调研外设方面，文件系统与内核耦合程度，耦合程度低，且syscall会被转换为sel4 like的call这样的接口，去向外设分发任务
- 以fstat为例
  - thread a发起fstat syscall 
  - 陷入内核，获取thread打开文件相应状态
  - 执行call，并把当前thread block，call类似于sel4中对endpoint的call
  - 该thread等待被唤醒，且任务状态为已完成后再继续运行
