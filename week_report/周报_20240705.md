## 中断处理

- 使用Rust async逻辑

  ```rust
  //示例
  let mut executor = Executor::new();
  executor.spawn(Task::new(example_task()));
  executor.spawn(Task::new(keyboard::print_keypresses()));
  executor.run();
  ```

- spawn向executor注册新的task，每一个task都对应一个具体中断，如`print_keypresses`监测键盘输入

- `run`函数不返回，需要在run之前对每一个需要监听中断调用spawn

- run函数轮询等待队列，查看是否有待完成的中断请求，如果有就去执行。如果没有放弃cpu，调度其他thread

- interrupt_handler只负责唤醒等待每个中断的task，不执行具体中断处理逻辑。

  - 问题：有些中断不可异步处理，不适配这个逻辑

## endpoint

- 将endpoint移植到rcore进行测试。rcore有完整的线程模型等，可以测试用户态通过syscall陷入内核态后，现有的endpoint是否能够进行函数回调

- 发现的问题：

  - executor:exec如何执行，放在哪里执行。原始设计中，exec无法返回，executor需要有自己单独的执行上下文(kernel thread)
    - 解决方案：exec仅轮询所有可执行的task，在每次线程schedule时运行调用exec函数
  - endpoint:send,原始设计中send操作调用std::condvar实现线程的阻塞和唤醒
    - 实现condvar的async_wait/async_signal逻辑，在阻塞线程后立即调度，转去executor:exec,执行send要求的回调函数后唤醒阻塞的线程，再通过调度算法找到就绪态线程，继续运行
    - 假设只有一个线程，如果第一次exec无法完成task，调度器将重复执行exec函数，直到该线程就绪为止。但如果有多个就绪态线程，当前阻塞的线程有可能会等待较长时间。

- 目前ep的功能示例：

  - blocking_send：

    ```rust
    //syscall:thread.rs:sys_get_tid()
    let dummy_buf = Box::new(IPCBuffer::default());
    let ep2=Endpoint::new(async_current_task);//async_current_task获取当前tcb,该函数位于另一个crate(rcore中是位于另一个mod)
    let task=ep2.send(dummy_buf.clone());//阻塞在这里，直到返回值(task)就绪
    task.unwrap()//获取task的tid
    .inner_exclusive_access()
    .res
    .as_ref()
    .unwrap()
    .tid as isize
    ```

  - nb_send:

    ```rust
    fn callback2(_: Box<IPCBuffer>) {
        println!("callback of nb_send triggerd");
    }
    
    let ep3=Endpoint::new(callback2);
    ep3.nb_send(dummy_buf.clone());//不会阻塞在这里，会直接print下面一行，稍后在exec执行时打印<callback of nb_send triggerd>
    prinln!("nb_send sended");
    ```

  - exec:

    ```rust
    pub fn exec(&self) {
        while let Some(todo)=self.ready_queue.nb_recv(){//检查队列是否有任务
             let waker = Arc::new(ChannelWaker::new(Arc::clone(&todo))).into();
             match todo.fut.lock().as_mut().poll(&mut Context::from_waker(&waker)) {//执行任务
                 Poll::Pending => println!("this one is pending"),
                 Poll::Ready(_) => println!("finish one")
             };
        }
    }
    ```
